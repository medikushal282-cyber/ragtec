# RAGSec Comprehensive Project Documentation

## 1. Project Overview
**RAGSec** (Retrieval-Augmented Generation for Cybersecurity Threat Intelligence) is a robust, enterprise-grade Security Operations Center (SOC) platform. It implements the IEEE RAGSec framework to assist security analysts in investigating cyber threats. By combining Time-Aware Retrieval-Augmented Generation (RAG), Automated Threat Intelligence, File Integrity Monitoring (FIM), and Human-in-the-Loop (HitL) workflows, the platform provides highly accurate, verifiable, and secure AI-driven security analysis while strictly preventing AI hallucinations.

---

## 2. Architecture Overview
The platform uses a decoupled client-server architecture:

1. **Frontend (SOC Analyst UI)**: A modern web application built with **React, TypeScript, Vite, and TailwindCSS**. It provides the interface for analysts to view live telemetry, chat with the AI for threat investigations, manage network fleets, and approve mitigation actions.
2. **Backend (Python AI Core)**: A high-performance **FastAPI** server that orchestrates the heavy lifting. It manages:
   - **Ingestion**: Normalizing Threat Intelligence (CTI) files, system logs, and FIM events.
   - **Vector Database**: A **ChromaDB** persistent index that stores document embeddings generated by `BAAI/bge-small-en-v1.5`.
   - **Retrieval Engine**: A 2-stage retrieval pipeline using Dense Embeddings and a Cross-Encoder Reranker (`ms-marco-MiniLM-L-6-v2`) to surface the most relevant threat intel.
   - **Generation**: Connects to a local **Ollama (`llama3.2`)** model to generate responses based *only* on retrieved evidence.
   - **Governance & Verification**: Pre-generation PII masking and post-generation lexical consistency checks (CRC) ensure the AI never leaks sensitive data or hallucinates facts.
3. **Database**: A lightweight **SQLite** database (`ragsec.db`) persisting audit logs, whitelist rules, entity relationships, and active incidents.

## 3. Comprehensive File Explanations

For each file in the project, we provide a detailed technical overview, followed by a "baby/grandpa" explanation that simplifies the concept.

### A. Core Application Files
* **`app.py`**
  * **Technical**: The main FastAPI entrypoint. Mounts all routers, configures CORS, and manages the application lifespan (including starting the `FIMWatcher` background thread on boot).
  * **Grandpa Version**: This is the front door of our factory. It unlocks the doors in the morning, turns on the security cameras (the file watcher), and makes sure data is allowed to enter and leave the building.
* **`config.py`**
  * **Technical**: Uses Pydantic `BaseSettings` to manage environment variables, paths, database URIs, model identifiers (e.g., `bge-small-en-v1.5`), and hardcoded math thresholds for the severity engine.
  * **Grandpa Version**: This is the factory's rulebook. It contains the master settings, like what language we speak, where we store the boxes, and exactly how strict we need to be when checking for errors.
* **`models.py`**
  * **Technical**: Defines Pydantic data schemas representing Incidents, Security Events, Evidence, Sensitivity Tiers, and Query payloads. This ensures type safety across the Python backend.
  * **Grandpa Version**: These are the blank forms and templates we use in the office. They make sure everyone fills out reports the exact same way so there's no confusion.

### B. API Routing Files (`ragsec/backend/api/`)
* **`api/routes.py`**
  * **Technical**: Exposes the main RAG REST endpoints: `/api/query` for chat generation, `/api/retrieve` for vector search, and `/api/ingest` for loading documents into ChromaDB.
  * **Grandpa Version**: This is the customer service desk for the AI. If you want to ask the AI a question or hand it a new book to read, you give it to this desk.
* **`api/soc_routes.py`**
  * **Technical**: Serves SOC telemetry data. Handles HTTP GET/POSTs for fetching device topology, network arrays, incident timelines, dashboard metrics, and mitigation actions.
  * **Grandpa Version**: This is the customer service desk for the dashboard. It gives your computer screen all the numbers, charts, and alerts it needs to show you what is happening on the network.
* **`api/fim_routes.py`**
  * **Technical**: Exposes endpoints for managing File Integrity Monitoring. Handles `/api/fim/quarantine` (to isolate files) and `/api/fim/whitelist` (to ignore false alarms).
  * **Grandpa Version**: This is the desk for the security guards. You call this desk when you want to lock a suspicious file in a safe, or tell them to ignore a file because it belongs to you.

### C. Database & Domain Logic (`ragsec/backend/db/` & `domain/`)
* **`db/database.py`**
  * **Technical**: A SQLite wrapper managing cursor execution, connection pooling, and schema migrations. Saves logs, incidents, and chunk metadata to `ragsec.db`.
  * **Grandpa Version**: The filing cabinet manager. It opens the drawers, puts files in exactly the right folder, and locks it up when it's done.
* **`domain/soc_models.py`**
  * **Technical**: Python dataclasses handling the object-oriented structure of a network, routing endpoints, host devices, and physical topology.
  * **Grandpa Version**: A digital map of our entire company's computer network. It knows exactly how the computers are connected with wires.
* **`domain/mitigation.py`**
  * **Technical**: Manages the Human-in-the-Loop state machine for responding to threats. Transitions mitigations through `RECOMMENDED` -> `APPROVED` -> `EXECUTED` -> `VERIFIED` and writes to the audit log.
  * **Grandpa Version**: The approval stamp machine. It takes a suggestion (like "unplug computer #4"), puts it on a human's desk for review, and makes sure they stamp "Approved" before anyone touches a plug. It also keeps a receipt.
* **`domain/ingestion.py`**
  * **Technical**: Normalizes raw telemetry from different systems (FIM, IDS, Syslog) into a standardized `SecurityEvent` schema before passing it to the pipeline.
  * **Grandpa Version**: The translator. People submit complaints in English, Spanish, and French, and this script translates them all into a standard English form so the bosses can understand them all identically.

### D. Generation & Governance (`ragsec/backend/generation/` & `governance/`)
* **`generation/generator.py`**
  * **Technical**: Abstracts the LLM client (Ollama/Gemini), handles network requests to the inference server, and parses the generated output.
  * **Grandpa Version**: This is the person who actually picks up the phone and talks to the artificial intelligence brain to get the answer.
* **`generation/prompts.py`**
  * **Technical**: Constructs the final prompt string. Crucially, it applies regex to redact PII, IP addresses, and hostnames (Compliance Buffer) to prevent sensitive data leakage.
  * **Grandpa Version**: The censor. Before we hand our private company files to the AI brain, this script takes a thick black marker and crosses out any private names, passwords, or addresses.
* **`governance/policy.py`**
  * **Technical**: Enforces similarity and confidence thresholds based on incident severity. Short-circuits generation and forces an `ABSTAINED` response if thresholds aren't met.
  * **Grandpa Version**: The strict manager. If the situation is an emergency, they won't let the AI speak unless the AI is 100% positive it is right. If the AI is guessing, the manager covers its mouth and says "We don't know."
* **`governance/confidence.py`**
  * **Technical**: Calculates a normalized confidence score based on the mathematical cosine distance of retrieved vectors.
  * **Grandpa Version**: The calculator. It looks at how closely the AI's books match your question and gives it a score out of 100 on how confident we should be.
* **`governance/abstention.py`**
  * **Technical**: Generates the standardized fallback string that explains to the analyst why the query was rejected by the policy engine.
  * **Grandpa Version**: The apology letter writer. It writes the exact polite sentence saying, "Sorry, I am not confident enough to answer this safely, please ask a human."

### E. Ingestion, Telemetry, and Pipeline (`ragsec/backend/ingestion/` & `pipeline/`)
* **`ingestion/loader.py`**
  * **Technical**: Parses markdown, JSON, or CSV raw text and standardizes it into a `CanonicalDocument` with metadata tags.
  * **Grandpa Version**: The mailroom clerk. It opens the envelopes, staples a tracking number to the top, and figures out what type of document it is.
* **`ingestion/entities.py`**
  * **Technical**: Applies Natural Language Processing (NLP) and Regex heuristics to identify IPs, Hashes (MD5/SHA256), CVE numbers, and Threat Actors in text.
  * **Grandpa Version**: The highlighter. It reads the whole page and uses a yellow marker to highlight any important numbers, names, or computer addresses so they are easy to spot later.
* **`ingestion/fim/watcher.py`**
  * **Technical**: Wraps the Python `watchdog` library to hook into OS file-system events, monitoring `monitored_workspace/` for created/modified/deleted events.
  * **Grandpa Version**: The security camera. It stares at a specific folder 24/7 and yells if someone adds, deletes, or changes a file inside it.
* **`pipeline/event_pipeline.py`**
  * **Technical**: The stateful engine that aggregates raw security events. If multiple events correlate, it generates an `Incident` ticket.
  * **Grandpa Version**: The detective's corkboard. It pins a bunch of separate suspicious clues to a board. If it connects three clues with red string, it officially opens a "Case."
* **`pipeline/classifier.py`**
  * **Technical**: Contains 10 heuristic rules (Regex/Substring matching) to categorize events into types like Malware, Ransomware, Lateral Movement, or DDoS.
  * **Grandpa Version**: The sorting hat. It looks at a piece of bad news and decides if it belongs in the "Hacker" bucket, the "Virus" bucket, or the "Broken Computer" bucket.

### F. Retrieval & Verification (`ragsec/backend/retrieval/` & `verification/`)
* **`retrieval/chunker.py`**
  * **Technical**: Uses sliding windows to break large strings of text into 500-token chunks with overlap, ensuring context boundaries are preserved.
  * **Grandpa Version**: The scissor. It cuts long, boring encyclopedias into small, bite-sized paragraph cards so they are easier to read and search.
* **`retrieval/embedder.py`**
  * **Technical**: Initializes the `SentenceTransformer` model to map a text string into a 384-dimensional vector space.
  * **Grandpa Version**: The translator. It takes English sentences and turns them into complex math coordinates that the computer understands.
* **`retrieval/vector_store.py`**
  * **Technical**: Interfaces with ChromaDB to persist embeddings. Performs Approximate Nearest Neighbor (ANN) cosine similarity search.
  * **Grandpa Version**: The gigantic mathematical filing cabinet. You hand it some math coordinates, and it instantly finds the closest matching folders.
* **`retrieval/reranker.py`**
  * **Technical**: Uses a Cross-Encoder (which compares query and document together via attention) to re-score and re-sort the top-50 dense retrieval results down to top-5.
  * **Grandpa Version**: The perfectionist editor. The cabinet gives it 50 *okay* results, and this editor reads them extremely carefully to pick out the absolute top 5 best ones.
* **`retrieval/retriever.py`**
  * **Technical**: The orchestrator function that strings together embedding, ChromaDB search, and cross-encoder reranking sequentially.
  * **Grandpa Version**: The manager of the library. You give them a question, and they coordinate the translator, the filing cabinet, and the perfectionist editor to hand you the final answer.
* **`verification/verifier.py`**
  * **Technical**: Executes Sentence-to-Evidence Lexical Grounding. It splits the LLM's generated response and verifies that the cited text actually exists in the source chunk.
  * **Grandpa Version**: The fact-checker. After the AI writes its report, this script goes through with a red pen and makes sure the AI didn't just invent facts that aren't in the original books.
* **`verification/citations.py`**
  * **Technical**: Extracts inline `[C1]` tags from LLM strings using regex and maps them to the UUIDs of retrieved chunks.
  * **Grandpa Version**: The footnote checker. It makes sure the little `[1]` numbers at the end of sentences point to the correct reference book at the bottom of the page.

## 4. Working Features

### Feature 1: RAG Threat Intelligence AI Assistant
**Detailed Technical Overview:**
The platform features an interactive AI assistant in the `ActiveIncident` view. When a query is submitted, it is embedded and matched against a ChromaDB vector index containing ingested Cyber Threat Intelligence (CTI). The system uses a two-stage retrieval process (Dense Embedding retrieval followed by Cross-Encoder reranking) to find the most relevant chunks of text. The context is masked of PII/IPs and fed into an Ollama LLM with strict systemic prompts forcing it to answer using inline `[C1]` citations. Finally, a CRC verification step checks the lexical consistency of the output against the retrieved chunks before presenting it to the user.

**Grandpa Explanation:**
Imagine you have a giant library of security manuals. Instead of making you read all the books when there's an emergency, you just ask our smart librarian a question. The librarian instantly reads millions of pages, finds the exact 5 paragraphs that solve your problem, and writes you a short summary. Better yet, the librarian highlights exactly which book and page number they got their facts from, so you know they aren't making things up!

---

### Feature 2: Severity-Aware AI Abstention (Anti-Hallucination)
**Detailed Technical Overview:**
Located in `governance/policy.py`, the system strictly prevents LLM hallucinations. Every incoming incident has a severity level (Low to Critical). The policy engine applies dynamic mathematical thresholds based on this severity (e.g., Critical incidents require a `0.70` cosine similarity confidence score). If the retrieved evidence scores below this threshold, the system intercepts the request before it reaches the LLM and forces an `ABSTAINED` response. This guarantees the AI will never guess or generate speculative answers during high-stakes incidents.

**Grandpa Explanation:**
You know how sometimes people will confidently give you bad advice just because they don't want to admit they don't know the answer? Our AI is strictly forbidden from doing that. If a problem is really serious and the AI isn't 100% sure it has the right facts in its manuals, it will simply raise its hands and say, *"I don't have enough evidence to answer this safely. A human needs to look at this."* It never guesses when safety is on the line.

---

### Feature 3: File Integrity Monitoring (FIM) & Quarantine
**Detailed Technical Overview:**
A background Python `watchdog` process continuously monitors a designated folder (`monitored_workspace/`). Whenever a file is created, modified, or deleted, it generates a hash (SHA256) and sends a normalized telemetry event to the SOC pipeline. If the file is deemed highly suspicious by the classifier, analysts are alerted on the dashboard. Analysts can then click a button to execute a `POST /api/fim/quarantine` request, which physically moves the malicious file into a secure, isolated `.quarantine/` directory, neutralizing the threat.

**Grandpa Explanation:**
We have a digital security guard standing outside your most important filing cabinet 24/7. The second someone tries to sneak a new file in, or tries to tamper with an existing document, the guard sounds an alarm on your dashboard. With the click of a button, you can tell the guard to instantly grab the suspicious file and lock it away in a safe where it can't do any harm.

---

### Feature 4: Human-in-the-Loop (HitL) Mitigation
**Detailed Technical Overview:**
Found in `domain/mitigation.py` and the `MitigationCenter.tsx` UI, this feature enforces a strict state machine for incident response. When a threat is detected, the system recommends an action (e.g., "Block IP at Firewall"). However, the AI cannot execute this action autonomously. A human analyst must review the action and explicitly click "Approve", shifting the state from `RECOMMENDED` to `APPROVED`, and then click "Execute". Every single transition is recorded with a timestamp and the analyst's ID into an immutable SQLite audit log (`ragsec.db`).

**Grandpa Explanation:**
Even though our computer system is very smart and can suggest how to fix a security breach (like unplugging a compromised computer), we never let the computer pull the plug by itself. It always writes up a proposal and puts it on a human's desk. A real human has to read it, stamp "Approved", and push the button. We also keep a permanent receipt of exactly who pushed the button and when, just to be safe.
